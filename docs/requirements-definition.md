## 1. 概要

### 1.1 事業背景

Hubらじおは、主に 16:9 の横長で収録される 10〜20 分の企業内向けトーク・インタビュー動画です（SRC-001 §2.1）。編集者が動画を最初から最後まで見て使える場面を手作業で探し、カット・文字起こし・字幕・テロップ・画角変換を個別に行っており、長尺版と短尺版を別々に編集するため、編集が特定の担当者に集中し、継続的な制作が難しい状態です。元動画 1 本を指定するだけで、社内向けの長尺版・短尺版・字幕・サムネイル・付帯情報を自動生成するソフトウェアで、この問題を解きます。

### 1.2 目的

| ID | 目的 | 成功指標 | 測定方法 |
|---|---|---|---|
| G-001 | 元動画 1 本から、長尺版・縦型短尺版・字幕・サムネイル候補・付帯情報を自動生成する | 元動画の選択から編集開始までの必須操作が 1 回の確認に収まる。成果物 set（長尺・短尺・字幕・サムネイル）が 1 回の実行で生成される | FR-001・FR-008〜FR-010 の受入基準（AC-049、AC-056〜AC-058）を System Test で確認 |
| G-002 | 編集作業の属人性を下げ、Project・Job の管理と設定を、利用者が迷わず変更・比較できるようにして継続的な制作を可能にする | 設定を変えた複数の Job を同じ Project 内で作成・比較できる。失敗時に原因と対応策が表示される | FR-036・FR-055・FR-061・FR-063 の受入基準を System Test で確認 |
| G-003 | 既定の公開範囲を社内限定とし、ブランド・機密・権利・AI 生成表示を守る | 社内限定以外の公開・外部投稿が行われない。存在しない氏名・肩書・URL を生成しない | NFR-SEC-001・NFR-BR-001〜005・NFR-FACT-001 の受入基準を結合試験で確認 |

受益者: 編集・広報の担当者（利用者）、視聴する社内の従業員。費用負担者・決定権者: 元文書に記載がなく、確認が必要です（§10.3 A-003）。

### 1.3 事業妥当性の判定

判定: 条件付き。根拠は元文書の背景と課題（SRC-001 §2）だけで、費用・効果の数値の出典がありません。条件: 編集時間の削減など効果の測定方法を、利用者が別途定めること（§10.3 A-003）。

## 2. 対象と対象外

対象（元文書 §4.1）: 単一 EXE の 1 操作起動、source-only quick start、版付き既定設定と設定画面、動画の取り込み、音声解析・話者識別・文字起こし、不要区間の検出、トピック・見どころの抽出、長尺版・縦型短尺版・字幕・強調テロップ・オープニング／エンディング・BGM と効果音・サムネイル・クイズ形式の生成、Opening／Closing 動画の結合、Project 一覧・Job の管理、プレビュー・修正・自動代理評価、出力、編集履歴と元動画との対応管理。

対象外（元文書 §4.2。初期リリース）: 外部への公開・直接投稿、出演者の発言内容の自動変更・実在人物の映像合成、権利未確認の外部素材の自動挿入、AI だけによる機密・法務の最終判断、ライブ配信中の編集、複数 Windows アカウント間の権限分離、インストーラー・自動更新・アンインストーラー、Windows 以外・Windows 10・ARM64。

## 3. 前提・制約

### 3.1 既定制約（要求定義プロンプトの常設方針）

- ui_policy-1 利用者がレイアウトを変更できるモダンな UI（決定状態: 承認済み・既定制約）。具体化は NFR-UX-002（AI提案／承認待ち）。
- ui_policy-2 ペルソナごとの既定の情報表現（決定状態: 承認済み・既定制約）。具体化は NFR-UX-003（AI提案／承認待ち）。
- 既定制約（元文書 §1・§4.2・NFR-004）: 出力は社内限定かつローカル成果物を既定とする。元動画は変更しない。決定論的で意味を変えない規則だけを自動適用する。対象は対応 Windows の標準ユーザー 1 名。

## 5. 利用シナリオ

- 主な流れ: 元動画を選択して Project を作成 → 設定が自動補完される → 1 回の確認で編集開始 → ジョブの状態を確認 → 仕上がりを Job ごとに見る → 出力。
- 代替: 設定を変えた Job を複数作り、映像と設定を比較する（FR-055・FR-063）。Opening／Closing を結合する（FR-035）。
- 失敗と復旧: 編集開始や自動編集が失敗したとき、原因と対応策を表示し、可能なものは自動修復する（FR-036・FR-047）。
- 変更と取消: Project の名前変更・削除、Job の取消・再試行（FR-037・FR-040・FR-046・FR-061）。

#### NFR-UX-003 ペルソナ別の既定の情報表現
- 要求: 利用者（編集担当者）が元動画と生成動画を確認するとき、時間に沿ったデータ（再生位置、使用区間・削除区間、字幕・テロップ、版）は、プレビューと時間軸（タイムライン）を既定の表現とし、Job 間の比較は並べた映像と設定の表で行う。同じデータを別の表現に切り替えても、選択中の対象・時刻・絞り込みが保たれる。視覚的な表現には、同じ情報を理解・操作できる表・テキストの要約・キーボード操作・支援技術の読み上げを備え、色だけで状態を示さない。ペルソナに応じた表示は利便性のためで、権限外の情報を表示しない。キャンバス型の自由配置は、この利用者の判断に必要でないため採用しない。
- 決定状態: AI提案／承認待ち　出自: AI提案　優先度: SHOULD（既存の仕上がり画面の見方と整合させるため。調査が未実施で根拠が弱い）
- 上位: G-002　出典: 既定制約 ui_policy-2、SRC-005（外部確認未実施の記録）、common.md §5（想定利用者）
- 対象エンティティ: 元動画, 成果物, Job　関係する状態: なし　参照パラメータ: なし
- 関連する既存資産: 仕上がり画面（FR-055・FR-063）、プレビュー（FR-026）
- 受入基準 AC-128: 編集担当者が仕上がり画面で表現を切り替えたとき、選択中の Job・時刻が保たれ、各表現に表またはテキストの代替があり、状態が色以外でも識別でき、権限外の情報が表示されない。
  - 検証レベル: integration
  - BLOCKED: Q-019（調査の実施範囲と既定表現の承認が未回答）
