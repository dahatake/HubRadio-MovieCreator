# ADR-0002: Windows 11ローカル優先の製品範囲

- 状態: Accepted
- 決定日: 2026-08-27
- タスク: P-002

> [!IMPORTANT]
> 2026-09-02以降、Stage 1の社内限定成果物に複数role/reviewを必須とする部分は[ADR-0009](ADR-0009-source-only-defaults-and-automated-evaluation.md)が置き換える。Windows単一PC、SQLite、local-first、非破壊、初期対象外の境界は維持する。以下は決定時点の履歴である。

## 決定

初期製品は、**Windows 11 24H2以降・x64・単一PC・単一アクティブ編集者**向けのデスクトップアプリケーションとする。

- UI: WinUI 3ホスト + WebView2内のReact静的UI
- 業務処理: 1つの.NETホストプロセス
- 永続化: SQLite + 管理ワークスペース
- 動画処理: ffprobe/FFmpeg子プロセス
- ローカルML: Python子プロセスまたはFoundry Local/Windows ML
- 通信: WebView2 WebMessageと子プロセス標準入出力。localhost HTTPサーバーは置かない
- クラウド: ローカル実測で不達となった文章提案だけをMicrosoft Azureの条件付き候補とする

## 利用形態

- 1つのWindowsアカウントが1台のPCで操作する。
- 同時共同編集、共有サーバー、複数PC同期は実装しない。
- 役割、レビュー、承認は同じPCでも別の監査イベントとして保持する。
- 元動画、代理、解析、編集版、納品物はアプリ管理ワークスペースへ格納する。

## データベース判断

Stage 0/1は単一PC・単一書込ホストであるためSQLiteを採用する。`implementation-research.md`のPostgreSQLは汎用参照構成の候補であり、本Windows構成ではこのADRが置き換える。複数PC共有が正式要件になるまでPostgreSQL移行層や抽象DB providerは作らない。

## リリース段階

### Stage 0

実素材で媒体、ASR、時刻、顔、シーン、字幕、レンダー、配布を測定し、採用・手動化・保留を決める。測定前の精度・時間目標は設定しない。

### Stage 1 — 要求定義§16のMust

動画取込、文字起こし、時刻、用語、削除候補、トピック、長尺、手動9:16、字幕、強調、オープニング/エンディング、プレビュー、手動編集、版、レビュー、出力、追跡性、権限、監査を、人が必ず完了できる経路として実装する。

### Stage 2 — 要求定義§16のShould

見どころ、フック、自動追尾、資料、音声補正、クイズ、投稿文、複数サムネイル、媒体別テンプレート、媒体UIマスクを追加する。Stage 1の手動経路を削除しない。

### Stage 3

公開履歴、運用改善、条件が確定した任意連携を追加する。C2PA、OTIO、WORM、分散基盤は正式な必要性と運用責任者が決まるまで導入しない。

## 初期対象外

要求定義§4.2と§16のWon'tに加え、次を初期対象外とする。

- 無人外部公開、YouTube/TikTok等への直接投稿
- ディープフェイク、口形/表情合成、発言内容の改変
- ライブ/リアルタイム編集
- 共同編集サーバー、マルチテナント、クラウドDB/ストレージ
- PostgreSQL、Cosmos DB、Service Bus、Temporal、AKS、マイクロサービス
- 汎用プラグイン基盤、二つ目の実装がないProvider/Factory
- Clipchampプロジェクト往復、OTIO、C2PA署名
- 任意URLの自動取得

## Azure境界

- 初期既定では動画、音声、画像、未選択の全文文字起こしを端末外へ送信しない。
- Azure候補へ送れるのは、人が選択し、必要ならマスクし、送信内容を確認した根拠付き文字起こしspanだけである。
- ローカル不達の実測、データ処理条件、リージョン、quota、ユーザーの作成指示が揃うまでAzureリソースを作らない。
- Azureを使えない場合も、手入力・抽出候補・手動編集で案件を完了できることを必須とする。

## 完了判定

このADRの範囲外機能は、要求変更と別ADRなしに実装へ持ち込まない。NFR-007は版付き契約と明確なモジュール境界で満たし、将来用の空拡張点は作らない。
