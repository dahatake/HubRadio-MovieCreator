# ADR-0005: ローカル保存、保持、バックアップ

- 状態: Accepted
- 決定日: 2026-08-27
- タスク: P-007

## 決定

単一PC版は、利用者が初回起動時に選択したローカル固定ディスク上の管理ワークスペースへデータを保存する。ネットワーク共有、同期フォルダー、リムーバブル媒体は初期既定にしない。

```text
<workspace>/
  hubradio.db
  projects/<project-id>/
    original/
    proxy/
    analysis/
    compositions/
    previews/
    renders/
    deliveries/
    evidence/
    staging/
  cache/
  models/
  logs/
  backups/
```

## データ種別

| 種別 | 性質 | 既定保持 | バックアップ |
|---|---|---|---|
| 元動画・登録素材 | 不変、再取得不能の可能性 | 明示削除まで | 含める |
| 代理、波形、sprite | 再生成可能 | 利用者が明示したcache清掃の対象 | 除外 |
| 解析成果物 | 再生成可能だが採否根拠 | 案件と共に保持 | 採用済みとModelRunを含める |
| Suggestionと採否イベント | AI/規則候補と人判断の監査根拠 | 案件と共に保持 | 採用・却下・修正をすべて含める。再生成可能な大容量raw特徴は除外可 |
| TranscriptRevision | 人修正を含む正本 | 明示削除まで | 含める |
| CompositionVersion/TimelineMap | 不変の編集正本 | 明示削除まで | 含める |
| Review/Approval/Audit/Rights | 統制記録 | 明示削除まで | 含める |
| Preview render | 再生成可能 | 利用者が明示したcache清掃の対象 | 除外 |
| Final render/Delivery | 納品物 | 明示削除まで | 含める |
| staging | 未確定作業 | 起動時整合性検査後に孤児だけ清掃 | 除外 |
| 診断ログ | 内容を含めないbounded log | サイズ上限で循環 | 除外 |
| モデル/ツールcache | hashで再取得可能な場合がある | 自動削除せず、利用者が明示したcache清掃の対象 | catalogとhashだけ含める |

## 削除

保持日数は要求と組織規定が未確定なため設定しない。時間だけを理由とする自動削除は行わない。

- 案件削除は対象一覧、元動画、承認、納品、監査への影響を表示し、明示確認を要求する。
- 元動画だけを先に削除して編集版を追跡不能にしない。
- キャッシュ削除は正本と納品物を対象にしない。編集中案件が参照する代理と、再取得可能性を検証できないモデル/ツールは削除候補にしない。
- import、proxy、解析、renderの開始前に、入力サイズと既知のprofileから必要容量を見積もり、空き容量不足が予測される場合は開始を保留する。予測不能な処理では利用者へ必要量が不確実であることを表示する。
- staging清掃はDBから参照されず、`running` jobでなく、`interrupted` jobの再開/破棄判断も済んだものだけを対象にする。heartbeat切れだけで孤児とみなさない。
- 容量不足時も正本を自動削除しない。利用者へ再生成可能cacheの内訳を示し、明示選択を求める。

## バックアップ

- SQLite online backupと、上表で「含める」としたファイルを一時バックアップディレクトリへコピーする。
- ファイルごとに相対パス、サイズ、SHA-256を記録する。
- 全ファイルのcopy/hash検証後にmanifestを最後に書き、完成マーカーを付けてから最終名へ原子的に昇格する。途中失敗した一時バックアップは復元候補に表示しない。
- 既定のDB migration前バックアップはワークスペース内`backups/`へ作成する。これは論理破損への復旧用であり、同一ディスク故障を防がないことを表示する。
- 元ワークスペースと異なるローカル固定ディスクへの完全バックアップを推奨し、利用可能な保存先を利用者が選択する。保存先がないことを「保護済み」と表示しない。
- スケジュールは未決のため、初期実装は手動バックアップとDB migration直前バックアップを提供する。
- SQLiteにはin-progress WorkingCopyを含む全業務行を保存し、完全バックアップには未承認CompositionVersionと関連成果物も含める。
- 復元は一時領域へ全件展開し、manifestに列挙した件数・サイズ・hashとSQLite `integrity_check`を通してから一括切替する。1件でも欠落・不一致なら全体を失敗扱いにし、現行ワークスペースを保持する。
- 復元中断後の一時領域は次回起動時に未完成として隔離し、利用者の確認後に削除する。

## セキュリティ

ワークスペースACLを現在のWindows SID、SYSTEM、必要な管理主体に限定し、全子ディレクトリ、staging、ローカルbackupへ継承・検証する。完全バックアップ先にも同等のACLを設定できることを検査する。

暗号化バックアップは鍵回復要件が未決のため独自暗号方式を初期既定にしない。社内限定以上のデータを外部固定ディスクへ保存する場合、BitLocker等のボリューム暗号化を確認し、暗号化も同等ACLも確認できない保存先へのバックアップを保留する。
