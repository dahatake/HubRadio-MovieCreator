**文書種別:** 要求定義書

**対象:** Hubらじお、および同種の企業向けトーク・インタビュー動画

**版:** 0.2 Draft

**初版作成日:** 2026年8月26日

**再baseline日:** 2026年9月2日

**状態:** 要求再baseline済み。production実装を再開し、`V2-001`設定domain/schemaを実装済み

**既定値の根拠:** [既定設定調査](dev/research/default-settings-research.md)

**設計判断:** [ADR-0009](dev/decisions/ADR-0009-source-only-defaults-and-automated-evaluation.md)

## 1\. 文書の目的

本書は、利用者が**編集前動画を1本指定するだけ**で、企業内向けに収録されたトーク、対談、インタビュー、製品解説から、社内向け長尺版、短尺版、字幕、サムネイル、付帯情報を生成するソフトウェアに求められる要求を定義する。

本書は「何を実現すべきか」を定義するものであり、特定のプログラミング言語、動画編集ライブラリ、クラウドサービス、AIモデル等の実装方法は原則として固定しない。

基本方針は次のとおりとする。

1. 元動画を変更せず、自動処理結果を元発言、元映像、許可済み素材まで追跡できるようにする。
2. 元動画以外の入力は版付き既定設定から補完し、全設定を専用設定画面で確認、変更、初期化できるようにする。
3. 決定論的で意味を変えない規則は自動適用し、判断不能な結果は警告または候補として残す。
4. 読みやすさ、分かりやすさ、安全性を自動代理評価で機械検査する。
5. 自動代理評価を、人による知覚、理解、法的判断を実施した証拠とは表記しない。
6. 出力は社内限定かつローカル成果物を既定とし、任意に確認、修正、再生成できるようにする。

# 2\. 背景と課題

## 2.1 背景

現在のHubらじおは、主に16:9の横長形式で収録された、10分から20分程度の企業内向けトーク動画である。

今後は、元動画だけを指定して次の社内向け成果物を一括作成したい。

1. 社内配信用の長尺版
2. 16:9横長版
3. 9:16縦型短尺版
4. 字幕焼き込み版と字幕なし版
5. 字幕、文字起こし、チャプター等の付帯物
6. サムネイル候補

YouTube、TikTok、LinkedIn等の仕様は出力profileの参考にするが、初期リリースは各サービスへの外部公開または直接投稿を行わない。

## 2.2 現状課題

- 編集者が動画を最初から最後まで見て、使える場面を手作業で探している
- カット、文字起こし、字幕、テロップ、画角変換を個別に行っている
- 長尺版と短尺版を別々に編集している
- 配信先ごとの縦横比や表示領域の違いに手作業で対応している
- テロップの用語、色、フォント、動きが動画ごとにばらつく
- 発言者名、製品名、社内用語の文字起こし誤りが発生する
- 10項目の必須入力と多段階レビューにより、元動画だけでは処理を開始できない
- 既定設定の値、根拠、適用範囲、初期値への戻し方を一か所で確認できない
- 元動画のどの部分から短尺動画を作成したか追跡しにくい
- 編集作業が特定の担当者に集中し、継続的な公開が難しい
- 機械試験と人の知覚評価が混同され、実施していない人手評価を完了扱いするリスクがある

# 3\. 目標

## 3.1 ビジネス目標

- 1本の元動画を選択してから、社内向け成果物の生成開始までの必須操作を1回の確認に収める
- 元動画以外の項目を安全な既定値で補完し、存在しない氏名、肩書、期限、URL、公開先を推測しない
- 1本の元動画から複数形式の動画を再利用可能にする
- 編集作業の属人性を下げる
- 長尺動画への入口となる短尺動画を継続的に制作できるようにする
- 重要な知識や発言を視聴者が短時間で理解できるようにする
- 既定の公開範囲を社内限定として管理する
- ブランド、字幕、音量、画面構成をシリーズ全体で統一する
- 編集結果を任意に確認、修正、再生成できるようにする
- 自動代理評価の合否、警告、未評価範囲を成果物ごとに確認できるようにする

## 3.2 成功状態

次の状態を満たすことを成功とする。

- 元動画を選択すると、安全な案件名、社内限定区分、版付き既定設定、成果物setが自動補完される
- 利用者が1回の確認で編集を開始できる
- 文字起こし、シーン候補、長尺、短尺、字幕、サムネイル候補が生成される
- 編集案ごとに、使用区間、削除区間、字幕、テロップ、画角、効果が確認できる
- 人が修正した内容を反映して動画を書き出せる
- 長尺版、短尺版、字幕ファイル、サムネイル案を一つの案件として管理できる
- 自動代理評価と任意のself-reviewを区別して確認できる
- 同じ入力、設定版、tool/model版から同じ編集計画を再生成できる

# 4\. 対象範囲

## 4.1 対象に含むもの

- source-only quick start
- 版付き既定設定と専用設定画面
- 動画ファイルの取り込み
- 音声解析
- 話者識別
- 文字起こし
- 無音、言い直し、重複発言の検出
- シーン、話題、重要発言の抽出
- 長尺版の編集案作成
- 短尺版の候補作成
- 縦型動画への再構成
- 字幕と強調テロップの生成
- オープニング、見出し、エンディングの挿入
- トランジションの適用
- BGM、効果音、音量の調整
- サムネイル候補作成
- クイズ・パズル形式への再構成
- プレビュー、修正、任意のself-review、自動代理評価
- 動画および関連ファイルの出力
- 編集履歴と元動画との対応管理

## 4.2 初期リリースの対象外

- 完全無人での外部公開
- YouTube、TikTok、LinkedIn等への直接投稿
- 外部公開用の運用承認、公開先アカウント管理、公開結果の保証

- 権利確認を行わずに外部素材を自動挿入すること

- ライブ配信中のリアルタイム編集
- 複数Windowsアカウント間の権限分離を初期release gateにすること
- 複数の出演者、コンテンツ、ブランド、権利担当による承認を社内限定成果物の必須gateにすること
- 社内法務部門の個別承認を初期release gateにすること

# 5\. 想定利用者

初期リリースの業務利用者は、現在のWindows標準ユーザーである**単一の利用者**とする。利用者は元動画の選択、自動結果と根拠の確認、任意の修正・self-review、社内限定成果物のローカル出力、設定変更を行える。

自動代理評価器、AI、Python worker、FFmpegは利用者または承認者ではない。actor SIDを持つ人の操作と区別したsystem actorとして記録する。将来複数利用者を追加する場合は、別要求、脅威分析、migrationを作成する。

# 6\. 入力要件

## 6.1 必須入力

システムは、案件作成時に**元動画ファイル1本だけ**を必須入力として受け付けること。

選択後、次を決定的導出または版付き既定設定で補完すること。

| 項目 | 初期値 |
| --- | --- |
| コンテンツ名 | 元ファイル名の拡張子を除いた名前 |
| 目的 | 社内向け再利用動画の自動編集 |
| 想定視聴者 | 社内視聴者 |
| 公開範囲 | 社内限定 |
| 言語 | 自動検出、不能時`ja-JP` |
| 出演者 | 匿名話者ラベル。氏名・肩書は空 |
| 期限 | なし |
| ブランド | 内蔵ニュートラル、ロゴなし |
| 成果物set | 16:9長尺1本、9:16短尺候補3本、字幕焼込版、字幕なし版、字幕file、サムネイル候補3枚 |

匿名、なし、ニュートラル等の安全な値を使い、氏名、肩書、期限、URL、外部公開先を推測してはならない。

## 6.2 任意入力

- 企画書
- 台本
- アジェンダ
- 出演者の正式な氏名と肩書
- 製品名、サービス名、社内用語の辞書
- 関連するPowerPointまたは画像
- 参考URL
- 使用可能なロゴ
- 使用可能なBGM、ジングル、効果音
- 編集してはいけない区間
- 必ず残す発言
- 外部公開不可の発言や情報
- 希望する動画時間
- 希望するトーン
- CTA、視聴後に促す行動

任意入力がないことを理由にquick startを拒否してはならない。

## 6.3 入力時の公開区分

quick startで作成する案件、素材、元動画内区間、編集版、出力物はすべて`社内限定`から開始すること。

- 子成果物が親より公開範囲を自動拡大してはならない。
- `Music/`由来素材は社内限定成果物だけに利用できる。
- 外部公開候補、外部公開承認済み等の既存区分はデータ互換のため保持できるが、本要求版の自動処理、受入、直接投稿の対象外とする。
- 公開不可または利用不可と利用者が指定した区間・素材は自動成果物に含めてはならない。

## 6.4 設定入力と版

- 全設定は専用設定画面から閲覧、変更できること。
- 各設定は現在値、初期値、用途、根拠区分、初期値に戻す操作を持つこと。
- 設定は「案件と出力」「編集」「字幕とグラフィック」「音声と素材」「プライバシーと保存」の5群にまとめること。
- 高度な設定は1段の展開UIへ置き、通常の動画指定画面へ露出しないこと。
- 新規案件には開始時の`DefaultSettingsProfile`のsemantic version、内容digest、snapshotを固定すること。
- 後日の既定値変更は既存版へ遡及適用しないこと。適用時は子`CompositionVersion`を作ること。
- 初期値、出典、根拠区分、適用範囲は[既定設定調査](dev/research/default-settings-research.md)を正本とすること。

# 7\. 基本処理フロー

1. 利用者が元動画1本を選択する
2. システムが安全な案件名を導出し、社内限定の版付き既定設定と成果物setを要約表示する
3. 利用者が`編集を開始`または取消を選ぶ。その他の項目入力は要求しない
4. 元動画を管理workspaceへ非破壊取込し、形式、stream、PTS、全編decode、容量を検査する
5. 代理動画、波形、preview索引、文字起こし、発話時刻、匿名話者、客観的な編集候補を作る
6. 明示カット、構造的な完全一致反復、版付き無音規則等の決定論的処理を子版へ自動適用する。曖昧な処理はwarningまたは候補に留める
7. 長尺、短尺、字幕、画角、音声、BGM、サムネイル、付帯情報を同じCompositionから生成する
8. codec、decode、duration、A/V同期、字幕、画面領域、音量、来歴を自動代理評価する
9. 自動代理評価が判断不能でも、社内限定成果物は未評価範囲とwarningを記録して出力できる。技術的破損または来歴欠落は出力を拒否する
10. 利用者は任意にpreview、差分、根拠へ移動し、修正、self-review、再生成できる
11. QC済み成果物だけをローカル納品領域へ昇格し、hash、元区間、設定版、編集履歴、評価結果を保存する

# 8\. 機能要求

## FR\-001 動画取り込み

システムは、一般的な動画ファイルを元素材として登録できること。

登録時に次の情報を取得すること。

- ファイル名
- 再生時間
- 解像度
- 縦横比
- フレームレート
- 音声トラックの有無
- ファイル容量
- 作成日時
- 登録者

破損、音声なし、極端な低解像度など、編集に影響する状態を検出した場合は警告すること。

## FR\-002 文字起こし

システムは動画の音声からタイムコード付き文字起こしを生成すること。

文字起こしは次の単位で管理できること。

- 話者
- 発話
- 文
- 単語
- 開始時刻
- 終了時刻
- 認識確度

利用者は文字を修正でき、修正結果を字幕とテロップへ反映できること。

## FR\-003 話者識別

システムは複数の話者を区別できること。

利用者は「話者1」等の仮名を正式な出演者名へ変更できること。

話者名の表示形式は、フルネーム、姓のみ、役割名、非表示から選択できること。

## FR\-004 用語辞書

システムは、製品名、人名、略語、社内用語などを案件またはシリーズ単位の辞書として保持できること。

文字起こしに辞書候補と異なる語が含まれる場合、修正候補を提示すること。

自動修正を行った箇所は利用者が確認できること。

## FR\-005 不要区間検出

システムは次の区間を検出し、理由、元区間、規則版を記録すること。

- 長い無音
- 言い直し
- 同じ内容の繰り返し
- 収録開始前後の準備会話
- 明らかな録画トラブル
- 話題から外れた区間
- 咳、雑音、操作待ち
- 「ここはカット」などの編集指示を含む発言

quick startで自動除外してよいのは、明示的な「ここはカット」、同一話者の構造的に隣接した正規化後完全一致反復、冒頭・末尾の2.0秒以上の無音という3種類だけとすること。無音短縮時は発話前後0.30秒を保持すること。これらは元動画を変更せず、子`CompositionVersion`の自動decisionとして記録し、利用者が無効化できること。

言い直し、内容の類似、脱線、咳、雑音等の意味または知覚判断を要する項目は自動削除せず、候補またはwarningとして利用者が確認できること。

上記の数値と自動適用範囲は[既定設定調査 §4.4](dev/research/default-settings-research.md#44-編集)に従うこと。

## FR\-006 トピック分割

システムは内容を意味的な話題単位に分割し、各トピックに次を付与すること。

- トピック名
- 開始時刻
- 終了時刻
- 要約
- 主な話者
- キーワード
- 重要発言候補
- 想定視聴者
- 公開上の注意候補

未採用modelが意味判定済みであると表示してはならない。利用可能な根拠だけで候補を作り、quick startは候補を使わなくても完了できること。利用者は境界とタイトルを修正できること。

## FR\-007 見どころ候補抽出

システムは短尺動画に利用できる候補を自動で複数作成し、既定では最大3本を成果物候補とすること。

候補選定時には次を考慮すること。

- 単独で意味が通じる
- 冒頭に問い、驚き、結論、問題提起がある
- 一つのテーマに集中している
- 視聴者に具体的な学びがある
- 発言の前後を切っても意味が変わらない
- 社内前提が強すぎない
- 長い前置きを必要としない
- 音声と映像の品質が使用可能である
- 公開区分に適合する

各候補について、選定理由と不足する文脈を表示すること。

候補がない場合に発言を捏造してはならない。長尺版だけを生成し、短尺候補なしの理由を記録すること。

## FR\-008 長尺版生成

システムは元動画から社内向け16:9長尺版を自動生成できること。

quick startではロゴ、出演者名、外部URLを推測せず、オープニング動画は無効、元ファイル名から導出した短いtitle overlayだけを使用すること。番組名、出演者紹介、まとめ、CTA、エンディングは根拠または設定値がある場合だけ使用すること。

利用者は開始・終了余白、title overlay、番組名、出演者紹介、本編、トピックcard、まとめ、CTA、エンディングを設定画面または編集画面で有効・無効にできること。

## FR\-009 YouTube横長版

システムはYouTube Studio Content Manager partner向け推奨値を参考にした、社内限定16:9動画を作成できること。このprofileを一般YouTube accountへのupload適合確認済みまたは公開承認済みと表示してはならない。

次を設定できること。

- 本編タイトル
- チャプター
- 左上または右上のトピック表示
- 発言者名
- 全文字幕または要約字幕
- 関連資料の差し込み
- CTA
- エンドカード用余白
- サムネイル候補

重要な映像、人物、テロップが画面外に出ないこと。

既定は1920×1080、MP4、H.264 High Profile、progressive、4:2:0、AAC-LC 48 kHz、BT.709、元素材frame rate維持とする。出典とbitrate等の条件は[既定設定調査 §4.3](dev/research/default-settings-research.md#43-映像出力)に従うこと。

## FR\-010 縦型ショート版

システムは、16:9の元動画から9:16の縦型動画を作成できること。

縦型化では次のレイアウトを選べること。

- 話者の顔を中心に自動追尾
- 2人の話者を上下に配置
- 話者映像と資料を上下に配置
- 資料を中央、話者を小窓表示
- 重要部分を自動拡大
- 背景にぼかした元映像を配置
- 固定テンプレートに映像を配置

顔、資料、コード、デモ画面など、主要対象を利用者が指定できること。

quick startでは1080×1920を使い、未採用のface detectorが対象を認識したと主張してはならない。人物または資料領域を確定できない場合は、元映像全体が失われない固定layoutまたはぼかし背景layoutへfallbackし、warningを記録すること。既定の目標尺は30秒、探索範囲は15〜60秒とするが、これは配信先の必須値ではなく製品判断として表示すること。

解像度と尺の根拠・適用範囲は[既定設定調査 §4.3](dev/research/default-settings-research.md#43-映像出力)に従うこと。

## FR\-011 フック生成

短尺版の冒頭には、視聴継続を促すフックを設定できること。

フックの形式は次から選択できること。

- 結論先出し
- 質問
- よくある誤解
- 数字や比較
- 禁止事項
- 失敗談
- 意外な事実
- 「あなたならどうするか」という問い
- 本編の最も印象的な短い発言

システムが作成したフックは、元発言の意味を変更しないこと。

元発言にない断定表現を、出演者の発言として表示しないこと。

quick startで自動採用できるフックは、元発言の連続区間または意味を変えない明示的抜粋だけとする。問いまたは結論を元発言の最初の3秒以内へ配置できない場合は、フックなしで開始すること。TikTokの3秒・6秒資料は広告向け構成ヒントであり、organic動画の必須条件または成果保証と表示してはならない。

フックの根拠・広告資料の適用範囲は[既定設定調査 §4.4](dev/research/default-settings-research.md#44-編集)に従うこと。

## FR\-012 字幕生成

システムは全文字幕を生成できること。

字幕は次を満たすこと。

- 発話タイミングと同期する
- 画面内に収まる
- 読み切れる単位で改行する
- 話者の発話より大きく先行しない
- 誤字を修正できる
- 句読点の表示有無を選択できる
- 字幕ファイルとしても出力できる
- 動画への焼き込み有無を選択できる

字幕には最低限、通常、強調、注意、引用のスタイルを設定できること。

quick startは`日本語SDH指向字幕候補`を既定とし、最大7全角文字/秒、横書き16全角文字/行、最大2行、cue最短$5/6$秒（約0.833秒）、最長7秒を用いること。cue間は最小2 frameとし、0.5秒未満のgapを2 frameへ閉じ、0.5秒以上のgapは保持すること。白文字、黒の不透明背景、自然な統語境界での改行、発話とshot changeに沿う同期を用いること。

自動生成だけで必要な非発話音、話者情報、主要内容理解の網羅性を保証してはならない。字幕の意味的完全性は既定で`NOT EVALUATED`とし、検出根拠があるcueだけを追加すること。

通常翻訳字幕の別profileとして、最大4全角文字/秒、横書き13全角文字/行、最大2行、最短$5/6$秒を選択できること。Netflix Japanese guide単独の最短0.5秒はGeneral/Timing guideと競合するため製品既定に採用しないこと。両profileを混同せず、出典と適用範囲は[既定設定調査 §4.5](dev/research/default-settings-research.md#45-日本語字幕)に従うこと。

16:9は字幕焼込版と字幕なし版、9:16は字幕焼込版を既定生成し、SRTまたはWebVTTも出力できること。

## FR\-013 強調テロップ

システムは全文字幕とは別に、重要ポイントを短いテロップとして表示できること。

強調テロップは次の条件で提案すること。

- 結論
- 数字
- 製品名
- 重要な注意事項
- 視聴者が覚えるべきキーワード
- 質問への回答
- 話題転換の要約

同一画面に過剰な文字を表示しないこと。

## FR\-014 テロップのタイミング

テロップは原則として、対象の発話開始と同時または直後に表示すること。

次の状態を避けること。

- 音声より大幅に先に答えが表示される
- 前の話題のテロップが残る
- 顔や資料の重要箇所に重なる
- 配信プラットフォームの操作ボタンに隠れる
- 複数の字幕、見出し、ロゴが競合する

利用者は開始、終了、位置、サイズ、色、アニメーションを調整できること。

字幕領域の既定は、BBC online guidanceを転用した汎用領域として、16:9で中央75%幅・中央90%高、9:16で中央90%幅・中央75%高の内側とすること。配信先UI maskが未測定または期限切れの場合は、固定pixel値を捏造せずこの領域へfallbackし、`platform UI未確認`warningを記録すること。TikTok、LinkedIn等への適合確認済みと表示してはならない。

領域とauthoring sizeの根拠は[既定設定調査 §4.5](dev/research/default-settings-research.md#45-日本語字幕)に従うこと。

## FR\-015 オープニング

システムは動画冒頭にオープニングを挿入できること。

オープニングには次を設定できること。

- 番組名
- エピソード番号
- タイトル
- 出演者
- ロゴ
- キービジュアル
- ジングル
- 公開区分

長尺版と短尺版で異なるオープニングテンプレートを使用できること。

短尺版では、本題に入るまでの時間を短くするため、オープニングを省略または簡略化できること。

quick startでは長尺・短尺ともオープニング動画を無効とし、長尺は短いtitle overlay、短尺は元発言から直ちに開始すること。利用者が有効化した場合だけ、許可済みロゴ、title、出演者、ジングルを使うこと。

## FR\-016 シーンチェンジ

システムはトピックが変わる位置にシーンチェンジを提案できること。

使用可能な効果は少なくとも次を含むこと。

- カット
- クロスフェード
- フェードアウト、フェードイン
- ワイプ
- スライド
- 短いタイトルカード
- 拡大または縮小

同じレベルの話題転換では効果を統一すること。

単なる言い直しや短いカットには、目立つトランジションを使用しないこと。

quick startの通常接続はduration `0 ms`のハードカットとする。`0 ms`はトランジションなしを表す製品上の定義であり、外部研究の推奨秒数とは表示しないこと。大きな話題境界は短いtitle cardを優先し、crossfadeは既定無効とする。利用者がcrossfadeを有効化した場合の初期値は250 msとし、製品判断として版管理すること。

transitionの外部知見と製品判断の区分は[既定設定調査 §4.4](dev/research/default-settings-research.md#44-編集)に従うこと。

## FR\-017 ジャンプカット緩和

不要発言を削除した結果、人物の位置や表情が不自然に飛ぶ場合、次のいずれかを提案すること。

- Bロール挿入
- 資料画面への切替
- 一時的な拡大
- カットアウェイ
- 短いクロスフェード
- 別カメラ映像への切替
- テロップによる視線誘導

存在しない映像を事実映像として生成しないこと。

自動適用は、同じ元動画、利用許可済み資料、決定的なcrop/zoom、既定のハードカットに限定すること。crossfadeを候補にする場合はFR-016の版付きdurationを使うこと。J-cut/L-cutは発話と無音境界から長さを導出し、根拠のない固定秒数を設定しないこと。

## FR\-018 資料・画像差し込み

利用者が関連資料を登録した場合、システムは発言内容に対応するページまたは画像の差し込み候補を提示すること。

差し込み時には次を指定できること。

- 全画面表示
- 話者との分割表示
- ピクチャー・イン・ピクチャー
- 指定領域の拡大
- 表示開始時刻
- 表示終了時刻
- 出典表記

機密資料や外部公開不可資料は、外部公開用動画に含めないこと。

## FR\-019 BGMと効果音

システムは、利用許諾範囲を記録した音源のみ使用できること。初期リリースではリポジトリ直下の`Music/`を、利用者が社内利用を許可したread-onlyローカルライブラリとして参照できること。

BGMは次の場所ごとに設定できること。

- オープニング
- 本編
- トピック切替
- クイズ出題
- 答え合わせ
- エンディング

会話中は音声の理解を妨げない音量に自動調整し、利用者が手動変更できること。

quick startでは、発話と重ならないtitle card、話題境界card、end cardが存在する場合だけBGM利用を有効とし、本編会話中は無効とすること。decode可能でcue以上の長さを持つtrackをlibrary snapshotの内容hash順で決定的に選択し、track digestを記録すること。ファイル名だけから曲調、権利、意味を推測せず、自動loopしてはならない。

`Music/`由来音源は社内限定成果物以外へ使用してはならない。本編会話中のBGMを利用者が有効化した場合は、foreground speechより20 dB低くduckする初期値を使えること。ただしこれはWCAG 2.2 SC 1.4.7のaudio-only Level AAA値を限定転用した製品判断であり、動画のLevel AA必須条件とは表示しないこと。

`Music/`が存在しない、空、または読み取れない場合はBGMなしで処理を完了し、warningと実際のlibrary状態を記録すること。音源を自動取得したり、別directoryを推測したりしてはならない。

自動処理だけで曲調、雰囲気、ブランドへの適合を保証してはならない。音楽的適合性は`NOT EVALUATED`と記録し、利用者が任意にpreview、変更、無効化できること。

20 dB差を機械測定できても、speechの知覚的理解またはmix品質をPASSとしてはならない。これらは`NOT EVALUATED`と記録すること。

BGMと20 dB値の限定的な適用範囲は[既定設定調査 §4.6](dev/research/default-settings-research.md#46-音声とbgm)に従うこと。

## FR\-020 音声補正

システムは次の音声補正を設定できること。

- 音量の均一化
- 左右バランス調整
- ノイズ低減
- ハムノイズ低減
- 無音区間調整
- BGMと音声のバランス調整
- 急激な音量変化の検出
- 音割れの警告

補正前と補正後を比較試聴できること。

quick startの音量測定はITU-R BS.1770-5に従い、online/internal profileは-16 LKFS、許容±1 dB、True Peak -1 dBFS以下を既定とすること。-16/-1はApple Podcastsのspoken-audio推奨を転用した製品判断であり、YouTube等の必須値とは表示しないこと。broadcast用の別profileとして-23 LUFSを選択できること。

音量均一化以外のnoise/hum reductionは自動提案に留め、quick startでは既定適用しないこと。適用時はbefore/after参照と設定値を保持すること。

loudness値の出典と転用範囲は[既定設定調査 §4.6](dev/research/default-settings-research.md#46-音声とbgm)に従うこと。

## FR\-021 サムネイル候補

システムは動画の実frameから既定3枚のサムネイル候補を作成できること。

候補には次を含められること。

- 出演者の画像
- 短いタイトル
- 番組ロゴ
- エピソード番号
- 背景画像
- ブランドカラー
- 公開区分

候補となるフレームでは、blur、露出、余白、文字との衝突等の客観値を評価できること。未採用modelで目、口、表情の意味を認識したと表示してはならない。

サムネイルの文言は動画内容と整合し、誤解を招く過度な表現を避けること。

生成顔、生成場面、元動画にない出来事を既定で使用してはならない。16:9 canvasは1280×720、9:16 canvasは1080×1920を製品既定として版管理し、配信先の普遍的必須値とは表示しないこと。

thumbnailの出典と製品判断は[既定設定調査 §4.7](dev/research/default-settings-research.md#47-サムネイル)に従うこと。

## FR\-022 クイズ・パズル形式

## FR\-024 CTA

## FR\-025 投稿付帯情報

社内限定quick startは、複数役割による承認を要求せず、自動代理評価の完了後に出力できること。

## FR\-032 元動画との追跡性

生成された各動画の各シーンについて、元動画の開始時刻と終了時刻を確認できること。

字幕、テロップ、要約が、どの元発言に基づくか追跡できること。

## FR\-033 設定管理

システムは全設定の現在値、初期値、用途、根拠区分、設定profile版を専用画面に表示すること。個別および全体の`初期値に戻す`を提供すること。変更は新規案件へ直ちに適用し、既存Compositionへ遡及適用しないこと。

## FR\-034 自動代理評価

システムは、keyboard event、focus順と可視style、contrast、accessibility tree、字幕の有無・読速・行長・同期・safe zone、全編decode、codec、duration、A/V同期、loudness、True Peak、来歴、設定版を機械判定できること。

評価結果は`PASS`、`WARNING`、`FAIL`、`NOT EVALUATED`を区別し、実行環境、規則版、入力・出力digest、判定詳細を記録すること。人の可読性、理解、自然さ、音質、感情、法的適合を実行したとは主張しないこと。

# 9\. 編集ルール

## 9.1 長尺動画の標準ルール

| タイミング | 標準処理 |
| --- | --- |
| 冒頭 | オープニング動画を置かず、短いタイトルoverlayを提示 |
| 話題開始時 | トピック見出しを表示 |
| 重要発言時 | 要約テロップを表示 |
| 資料説明時 | 該当資料を差し込む |
| 明示カット・完全一致反復・冒頭末尾無音 | FR-005の版付き規則を非破壊で自動適用 |
| 言い直し・脱線・雑音 | 自動削除せずcandidateまたはwarning |
| 通常接続 | ハードカット、duration 0 ms |
| 大きな話題転換 | 短いtitle cardを優先。crossfadeは既定OFF |
| 最後 | 根拠がある場合だけCTAまたはエンディングを表示 |

## 9.2 短尺動画の標準ルール

| タイミング | 標準処理 |
| --- | --- |
| 開始直後 | 元発言内に存在する質問、結論、問題提起を3秒以内へ配置できる場合だけ使用 |
| 冒頭部分 | オープニング動画を置かず、元発言から開始 |
| 本編 | 一つのテーマに限定する |
| 発話中 | 読みやすい字幕を同期表示する |
| 重要語 | 色だけに依存せず、太さ、背景、短い動きで強調する |
| 話者変更 | 必要に応じて画角または配置を変更する |
| 離脱しやすい間 | 不要な無音や重複を削除する |
| 終了前 | 結論または答えを提示する |
| 最後 | 対応する長尺版がある場合だけ`本編を見る`を一つ示す |

## 9.3 トランジションの標準ルール

- 同一会話内の軽微なカットはduration 0 msのハードカットを使用する
- 大きな話題転換ではタイトルカードを優先する
- crossfadeは既定で無効とし、有効化時の初期値は250 msとする
- ワイプやスライドはシリーズ内で用途を固定する
- 効果を目立たせること自体を目的にしない
- トランジションは発話内容の理解を妨げない
- 同じ動画に多数の異なる効果を混在させない
- 企業向け動画では、派手さより一貫性と視認性を優先する

`0 ms`と`250 ms`は製品上の版付き既定値であり、外部研究が直接推奨した値とは扱わない。

# 11\. 非機能要求

## NFR\-001 操作性

- 動画編集の専門知識が少ない利用者でも基本編集を完了できること
- 元動画1本の選択と1回の確認だけでquick startを開始できること
- 通常画面には元動画、既定設定の短い要約、開始・取消、進捗、成果物だけを表示すること
- 全設定は専用設定画面で現在値と初期値を確認できること
- タイムラインと文字起こしのどちらからでも編集できること
- 変更結果をすぐにプレビューできること
- 自動提案には理由を表示すること
- 自動decision、利用者decision、自動代理評価を明確に区別すること

## NFR\-002 性能

- 長い動画でも処理状況を確認できること
- 一部区間のみ再処理できること
- 字幕修正のために動画全体を再解析する必要がないこと
- プレビュー用の低解像度処理と最終書き出しを分離できること

## NFR\-003 信頼性

- 処理中断後に案件を復旧できること
- 元動画を変更せず保持すること
- 書き出し失敗時に原因を記録すること
- 同一入力、同一設定の出力条件を記録すること
- 既定値更新を既存版へ遡及適用しないこと
- 設定、tool、model、元動画の変更を検出し、別の子版または再評価として扱うこと

## NFR\-004 セキュリティ

- 現在のWindows標準ユーザーのper-user workspaceへ保存すること
- 別Windowsアカウントによるcross-account ACL受入を初期release gateにしないこと
- 社内限定動画を外部公開用保存先へ自動出力しないこと
- 直接投稿および外部destinationへのnetwork送信を既定で無効にすること
- 操作履歴を記録すること
- 元動画、文字起こし、出力動画に同一の情報保護方針を適用できること
- cloud AIは既定で無効とし、有効化時も選択・mask済み文字起こしspan以外を送信しないこと

## NFR\-005 アクセシビリティ

- 字幕を提供できること
- 通常文字と画像化文字は原則4.5:1以上、large textは3:1以上のcontrastを確保できること
- 色だけに依存しない強調表現を使用できること
- 全機能をkeyboard interfaceで操作でき、focus indicatorを表示すること
- 音声がなくても主要な内容を理解できること
- 自動試験可能な項目を自動代理評価し、人による可読性・理解の実施済み証拠と混同しないこと
- 必要な非発話音、話者情報、主要内容理解の網羅性は、自動的に証明できない場合`NOT EVALUATED`と表示すること

WCAG criterionのLevel、scope、数値は[既定設定調査 §4.8](dev/research/default-settings-research.md#48-アクセシビリティと自動代理評価)に従うこと。

## NFR\-006 監査性

次の履歴を保持すること。

- 誰が動画を登録したか
- 誰が字幕を修正したか
- 誰が公開区分を変更したか
- 利用者が任意確認を記録したか
- どのバージョンを出力したか
- どの元動画区間を使用したか
- AI生成部分と人が修正した部分
- どの設定profile、tool、model、規則で自動処理したか
- 自動代理評価の環境、規則版、結果、未評価範囲

## NFR\-007 拡張性

将来、次を追加できること。

- 多言語字幕
- 吹き替え
- 複数カメラ
- 外部動画プラットフォームとの連携
- 視聴データを使った改善提案
- シリーズ横断検索
- 共通素材ライブラリ
- 承認ワークフロー連携
- 自動チャプター生成
- 複数動画からの総集編生成

将来項目のために、実在する二つ目の実装がないprovider、factory、plugin基盤を先行実装してはならない。

## NFR\-008 事実性

- 自動生成した人名、肩書、期限、URL、引用、数値を根拠なしに確定してはならない
- 仕様、公式推奨、査読知見、広告資料、実務知見、製品判断、現行実装値を区別すること
- 配信先の広告仕様をorganic投稿の一般要件へ読み替えてはならない
- 未実施の人手評価、外部公開、法務承認、cross-account試験をPASSと記録してはならない
- 不成立の成果物は空または捏造内容で埋めず、理由を記録すること

# 15\. 受け入れ基準

## AC\-001 source-only quick startと長尺版

- 元動画1本以外を入力せず、既定設定の要約から1回の確認で編集を開始できる
- コンテンツ名、社内限定区分、言語fallback、匿名話者、ニュートラルtemplate、成果物setを安全に補完できる
- 16:9長尺版、字幕焼込版、字幕なし版、字幕file、文字起こしを生成できる
- 決定論的な不要区間処理を自動適用し、元区間、理由、規則版、取消可能性を確認できる
- 元動画の対応位置と適用した設定profileを確認できる
- 複数役割の承認なしで、自動代理評価済みの社内限定動画を書き出せる
- 人手で確認していない項目を`HUMAN EVALUATION: PASS`と表示しない

## AC\-002 縦型短尺版

- 16:9の元動画から9:16の動画案を作成できる
- 主要対象を確定できない場合も、安全な固定layoutへfallbackできる
- 一つのテーマに絞った候補を最大3本作成し、不成立時は理由を記録できる
- 元発言に存在するフックだけを採用し、元発言の意味を変えていないことを追跡できる
- 日本語SDH指向字幕候補を焼き込み、読速、行長、行数、同期、汎用safe zoneを自動代理評価できる
- 必要な非発話音・話者情報の網羅性を評価できない場合は`NOT EVALUATED`と記録できる
- 配信先UI maskが未測定の場合に、測定済みと表示しない

## AC\-003 クイズ版

- 元動画から問題、答え、解説を作成できる
- 答えの根拠となる元発言へ移動できる
- 出題から答えまでの待ち時間を変更できる
- 根拠が曖昧な問題を要確認として扱える

クイズ版はquick startの必須成果物ではなくShould機能とする。根拠がない場合は生成しない。

## AC\-004 セキュリティ

- 案件を現在のWindows標準ユーザーのper-user workspaceへ保存できる
- 別Windowsアカウントによる拒否試験を初期受入の必須条件にしない
- 社内限定成果物を外部公開可能または外部承認済みと自動表示しない
- 外部destinationへの出力と直接投稿を既定で実行しない
- cloud AIを既定で無効にし、明示有効化時も選択・mask済み文字起こしspan以外を送信しない
- 操作履歴を確認できる

## AC\-005 追跡性

- 出力動画の任意シーンから元動画の該当区間を確認できる
- AI生成字幕と人が修正した字幕を識別できる
- 使用素材と権利確認状態を確認できる
- `Music/`から使用したtrack digestと社内限定条件を確認できる
- 自動decision、利用者decision、自動代理評価を区別できる

## AC\-006 設定と自動代理評価

- 専用設定画面で全設定の現在値、初期値、用途、根拠区分、profile版を確認できる
- 個別項目と全項目を初期値へ戻せる
- 既定値変更が既存Compositionへ遡及適用されない
- codec、全編decode、A/V同期、字幕、safe zone、loudness、True Peak、来歴、UIのkeyboard/focus/contrast契約を自動評価できる
- `PASS`、`WARNING`、`FAIL`、`NOT EVALUATED`と実行環境を記録できる
- 自動代理評価が人の可読性、理解、自然さ、音質、感情、法的適合を実行したとは表示しない

# 20\. 完了条件

本要求定義の再baselineは、次を満たした時点で完了とする。

1. product ownerである利用者が、source-only quick start、社内限定、単一利用者、版付き既定値、自動代理評価、任意self-reviewを承認する。
2. 既定値ごとに仕様、公式推奨、査読知見、広告資料、実務知見、製品判断、現行実装値の区分と出典が記録される。
3. ADR-0003/0004/0005/0007との置換範囲をAccepted ADRに記録する。
4. 旧203 task baselineを歴史snapshotとして保全し、新要求への`維持`、`変更`、`削除`、`新規`を再分類する。
5. 文書整合性、出典scope、捏造防止の独立した敵対的レビューが完了する。

production実装、実素材render、human evaluation、外部公開、cross-account試験、社内法務承認は、この文書自体の完了条件ではない。
