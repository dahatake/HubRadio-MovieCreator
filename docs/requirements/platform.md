# 要求定義書: 非機能・ブランド・データ管理

索引と変更履歴は[要求定義書（索引）](../requirement-definition.md)にある。本書は、非機能要求（§11、NFR-001〜NFR-009）、ブランド・コンプライアンス要求（§12、BR-001〜BR-005）、データ管理要求（§13）と、その受入基準を収める。章・節の番号は分割前の要求定義書のまま使う。

# 11\. 非機能要求

## NFR\-001 操作性

- 動画編集の専門知識が少ない利用者でも基本編集を完了できること
- 元動画1本の選択と1回の確認だけでquick startを開始できること
- 通常画面には元動画、既定設定の短い要約、開始・取消、進捗、成果物だけを表示すること
- 全設定は専用設定画面で現在値と初期値を確認できること
- タイムラインと文字起こしのどちらからでも編集できること
- 変更結果をすぐにプレビューできること
- 自動提案には理由を表示すること
- 自動decision、利用者decision、自動代理評価を明確に区別すること

- UI/UX追補の標準基準は**1280×720 CSS px以上・Web zoom 100%**とし、通常4画面の主要操作・現在状態・標準成果物の種類、および設定の1page一覧と選択項目をページscrollなしで操作できること。モニター解像度と混同せず、実client領域・CSS viewport・Web zoom・OS表示倍率を記録すること。これは表示の製品基準であり、測定済み最小動作環境の保証ではない。
- 長文入力・全文字幕・timeline・任意根拠・拡大時は、内容領域のscroll／panやreflowを許容すること。例外でも必要な情報・操作へ到達でき、全体の見切れ隠蔽や文字・操作領域の極小化で無scrollを達成したと扱わないこと。

## NFR\-002 性能

- 長い動画でも処理状況を確認できること
- 一部区間のみ再処理できること
- 字幕修正のために動画全体を再解析する必要がないこと
- プレビュー用の低解像度処理と最終書き出しを分離できること

## NFR\-003 信頼性

- 処理中断後に案件を復旧できること
- 元動画を変更せず保持すること
- 書き出し失敗時に原因を記録すること
- 同一入力、同一設定の出力条件を記録すること
- 既定値更新を既存版へ遡及適用しないこと
- 設定、tool、model、元動画の変更を検出し、別の子版または再評価として扱うこと

## NFR\-004 セキュリティ

- 現在のWindows標準ユーザーのper-user workspaceへ保存すること
- 別Windowsアカウントによるcross-account ACL受入を初期release gateにしないこと
- 社内限定動画を外部公開用保存先へ自動出力しないこと
- 直接投稿および外部destinationへのnetwork送信を既定で無効にすること
- 操作履歴を記録すること
- 元動画、文字起こし、出力動画に同一の情報保護方針を適用できること
- cloud AIは既定で無効とし、有効化時も選択・mask済み文字起こしspan以外を送信しないこと

## NFR\-005 アクセシビリティ

- 字幕を提供できること
- 通常文字と画像化文字は原則4.5:1以上、large textは3:1以上のcontrastを確保できること
- 色だけに依存しない強調表現を使用できること
- 全機能をkeyboard interfaceで操作でき、focus indicatorを表示すること
- 音声がなくても主要な内容を理解できること
- 自動試験可能な項目を自動代理評価し、人による可読性・理解の実施済み証拠と混同しないこと
- 必要な非発話音、話者情報、主要内容理解の網羅性は、自動的に証明できない場合`NOT EVALUATED`と表示すること

- UI/UX追補では200%文字拡大および320 CSS px幅相当で非例外部を1方向にreflowさせ、情報・機能を失わずscrollを許容すること。timeline等の二次元操作の例外を画面全体へ拡張せず、固定header／footerもfocusを覆わないこと。
- navigation・主要操作のアイコンには常時見える短い日本語ラベルを併記し、状態を色だけで示さないこと。現行light/dark、可視focus、reduced-motionを維持すること。
- 状態タブはrole・選択状態・対応panelを整合させ、左右矢印／Home／Endでfocus移動、Enter／Spaceで選択できること。横タブで上下矢印を奪わず、非表示panelをfocus対象にしないこと。設定から戻ると呼出し元へfocusを戻し、進捗更新だけでタブやfocusを移さないこと。

WCAG criterionのLevel、scope、数値は[既定設定調査 §4.8](../dev/research/default-settings-research.md#48-アクセシビリティと自動代理評価)に従うこと。

## NFR\-006 監査性

次の履歴を保持すること。

- 誰が動画を登録したか
- 誰が字幕を修正したか
- 誰が公開区分を変更したか
- 利用者が任意確認を記録したか
- どのバージョンを出力したか
- どの元動画区間を使用したか
- AI生成部分と人が修正した部分
- どの設定profile、tool、model、規則で自動処理したか
- 自動代理評価の環境、規則版、結果、未評価範囲

## NFR\-007 拡張性

将来、次を追加できること。

- 多言語字幕
- 吹き替え
- 複数カメラ
- 外部動画プラットフォームとの連携
- 視聴データを使った改善提案
- シリーズ横断検索
- 共通素材ライブラリ
- 承認ワークフロー連携
- 自動チャプター生成
- 複数動画からの総集編生成

将来項目のために、実在する二つ目の実装がないprovider、factory、plugin基盤を先行実装してはならない。

## NFR\-008 事実性

- 自動生成した人名、肩書、期限、URL、引用、数値を根拠なしに確定してはならない
- 仕様、公式推奨、査読知見、広告資料、実務知見、製品判断、現行実装値を区別すること
- 配信先の広告仕様をorganic投稿の一般要件へ読み替えてはならない
- 未実施の人手評価、外部公開、法務承認、cross-account試験をPASSと記録してはならない
- 不成立の成果物は空または捏造内容で埋めず、理由を記録すること

## NFR\-009 配布と初回起動

- サポート中のproduction-channel Windows 11 24H2以降のx64を初期対象とする。試験したedition、version、buildを記録し、未検証のeditionや構成を対応済みと表示しないこと。
- OS以外の開発・実行環境を利用者が事前導入していなくても、保存済み単一EXEへの1回の起動指示（ダブルクリックまたはEnter等）で、既存UIを操作可能にすること。取得操作はこの1操作に含めず、取得後の手動ZIP展開やセットアップ操作を要求しないこと。
- 配布単位を1ファイルとする。内部の依存ファイル展開と必要な子プロセスは許容するが、展開不要または単一プロセスと表示しないこと。
- 利用者によるGit、SDK、.NET/Windows App SDK/WebView2等のRuntime、Node.js、Python、pip、PowerShell 7、FFmpeg、GPU用追加Runtimeの手動導入を必須にしないこと。
- 管理者昇格、OS再起動、Azureログイン、API key、環境変数の手動設定を起動の必須操作にしないこと。取得後の初回起動と既定ローカル経路で依存downloadを必要としないこと。
- 実行依存の展開領域と、現在の標準ユーザーの案件・DB・設定・WebView2ユーザーデータを分離すること。再起動や依存の再展開を理由に利用者データを削除しないこと。
- 配布物の依存版、内容digest、第三者notice、再配布条件を記録すること。保留・不同意・非採用モデルを新たに取得・追加同梱・有効化せず、未許可の動画・音源、秘密情報を同梱しないこと。既存の固定runtime wheelに内包され台帳で把握済みの付随資産は、その固定・許諾・notice契約を維持する。同梱をモデルの採用・実行許可・一般配布承認とはみなさないこと。
- 初回展開・再起動の時間、最初の可視UIまでの時間、配布・展開・モデルcacheの容量を実測すること。最小ハードウェア、空き容量、許容時間を未測定の固定値で保証しないこと。
- Windowsや組織の保護を無効化しないこと。署名、SmartScreen、Smart App Control等の確認・拒否があり得ることと、実配布経路の信頼条件を明示し、全端末・全状態で無警告の1操作起動を保証しないこと。
- ローカル技術検証、署名後の一般提供向け起動受入、AC-001〜006の業務受入を区別すること。署名や配布先の未選定だけで許諾済み技術検証を停止しないが、未署名試作の結果を一般提供の合格にしないこと。
- インストーラー等は§4.2の将来事項とし、当面の更新は終了後の手動差替えとすること。既存migration/backupを維持し、DBのdowngrade互換性を推測して保証しないこと。

- UI/UX追補の`setting.txt`は、nativeが確定するper-user app root直下の固定名`%LOCALAPPDATA%\HubRadio.MovieCreator\setting.txt`へ保存すること。Workspace、EXE隣、WebAssets、自己展開cacheへ置かず、Webからraw pathを受け取らないこと。利用者固有の設定fileを配布物へ同梱しないこと。
- このexportは現行backupの対象外とし、実行設定はDB backupで保全すること。workspace restoreでもexportを変更・自動適用せず、再読込は復元後DBのprofile／revisionを再照合すること。export自体の別途保全は利用者の明示コピーとすること。
- 一時fileと完成fileに現在actor／SYSTEM／Administratorsを想定したfile ACL・所有者の境界を設定・確認し、操作前後のpath安全性を検査すること。reparse point・非通常file・不正rootを拒否し、既存app root全体のACLを変更しないこと。安全性・権限を確認できないfile操作だけを拒否し、file欠落や読書き失敗で既存DBの利用・起動を妨げないこと。設定内容・個人pathを通常ログへ出さず、自由入力をprivateな利用者データとして扱うこと。別accountでの実アクセス拒否試験を新しい必須gateにはしないこと。

本要求はアプリ自体の起動を対象とし、元動画選択後のquick startの開始確認（NFR-001、AC-001）とは別の操作である。具体的な同梱・自己展開方式は後続の設計判断で定める。

# 12\. ブランド・コンプライアンス要求

## BR\-001 ブランド一貫性

- quick startはロゴなしの内蔵ニュートラルテンプレートを使用すること
- ロゴ、色、フォント、モーション、写真、音源を追加する場合は利用可能と記録された素材と版付きテンプレートを使用すること
- ブランドテンプレートを案件ごとに勝手に変更できない設定を用意すること
- オープニング、テロップ、サムネイル、エンディングの一貫性を保つこと

## BR\-002 人物・役職

- 出演者の氏名と肩書を確認できること
- 肩書に確認日または収録時点を保持できること
- 肩書や所属が未確認の場合は警告すること
- quick startでは氏名と肩書を必須入力にせず、匿名話者ラベルを使用すること

## BR\-003 機密情報

次を含む可能性がある箇所を要確認候補として表示すること。

- 顧客名
- 未公開製品
- 内部URL
- メールアドレス
- 個人情報
- 画面上の認証情報
- 契約、価格、売上情報
- 社外秘の資料
- 将来計画
- アクセストークンや秘密情報

AIまたは自動代理評価の判定だけで外部公開可としないこと。社内限定quick startでは候補をwarningとして記録し、利用者が任意に確認・保護区間指定できること。

## BR\-004 権利管理

- 動画、画像、音楽、ロゴ、資料ごとに使用権の確認状態を保持すること
- 権利確認が未完了の素材を含む場合は外部公開用出力時に警告すること
- 素材の出典と利用条件を記録できること
- `Music/`は利用者が社内利用を許可したローカルライブラリとしてread-only参照し、各使用trackの内容digestと社内限定条件を記録すること
- `Music/`由来素材を外部用profileへ自動利用してはならない
- 社内法務部門の個別承認を初期release gateにしない。ただし第三者license、notice、利用規約、再配布条件の検査と記録は省略してはならない

## BR\-005 AI生成表示

AIで生成または大幅に編集した要素を記録できること。

必要な場合は、公開先のルールに応じた表示やラベルを追加できること。

# 13\. データ管理要求

1案件は次のデータを一体として管理すること。

- 元動画
- 代理プレビュー動画
- 文字起こし
- 登録資料
- 用語辞書
- シーン情報
- 編集案
- テンプレート
- 編集済み動画
- 字幕
- サムネイル
- 投稿文
- コメント
- 任意確認記録
- 自動代理評価記録
- 既定設定profileと案件snapshot
- 出力履歴
- 使用素材の権利情報

元動画は編集によって上書きしないこと。

# 15\. 受け入れ基準

## AC\-004 セキュリティ

- 案件を現在のWindows標準ユーザーのper-user workspaceへ保存できる
- 別Windowsアカウントによる拒否試験を初期受入の必須条件にしない
- 社内限定成果物を外部公開可能または外部承認済みと自動表示しない
- 外部destinationへの出力と直接投稿を既定で実行しない
- cloud AIを既定で無効にし、明示有効化時も選択・mask済み文字起こしspan以外を送信しない
- 操作履歴を確認できる

## AC\-007 OS-onlyの1操作起動

| 項目 | 受入条件 |
| --- | --- |
| AC-007.1 | 開発ツール・追加Runtimeを導入していない対象Windowsの標準ユーザーが、本体EXEへ1回起動指示を与えるだけで既存UIへ到達する |
| AC-007.2 | 同梱Web UIのbridgeが応答し、元動画選択と設定画面の既存操作へ到達できる。ウィンドウの存在だけを合格にしない |
| AC-007.3 | OS側のWebView2導入状態を前提にせず起動し、実際に使用するRuntimeの版・配置を配布物と照合できる |
| AC-007.4 | 配布候補内のPython health/protocol、必要なnative imports、FFmpeg/ffprobe、採用CPUモデルのoffline loadを独立に確認する。業務E2Eや認識精度の成功と混同しない |
| AC-007.5 | 管理者昇格、依存導入、手動設定、起動時downloadを要求しない。ユーザーデータは既存per-user領域に保存される |
| AC-007.6 | 終了・再起動・依存の再展開で設定や案件を失わず、アプリは配布EXEと展開済み実行依存を変更しない |
| AC-007.7 | 欠落・破損・容量不足・アクセス拒否を成功扱いしない。アプリの起動処理へ到達する前の障害も、OS/Runtime側の実際の結果と対処を記録する |
| AC-007.8 | cold/warm起動、最初の可視UIまでの時間、展開サイズ、ピーク占有量を記録する。許容値は実測後の合意対象とし、値が未確定の性能受入をPASSにしない |
| AC-007.9 | 一般提供時は、実配布経路と対象policyで署名・信頼動作を確認し、署名後の同じEXEで起動を再受入する。MOTWなしのローカルコピー試験を実ダウンロードのSmartScreen受入と表示しない |

ローカル技術検証では、評価利用が許される候補のAC-007.1〜8の実結果を記録できる。未署名・policy・環境制約を明記し、未測定・拒否・未設定による保留をPASSにしない。一般提供にはAC-007.9と供給網の条件も必要とする。AC-007の成立だけでAC-001〜006または製品全体を完了扱いにしてはならない。
