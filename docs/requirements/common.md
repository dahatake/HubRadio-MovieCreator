# 要求定義書: 全体（目的・範囲・利用者・入力・処理の流れ・優先順位・完了条件）

索引と変更履歴は[要求定義書（索引）](../requirement-definition.md)にある。本書は、要求定義書のうち、アプリ全体に共通する節（§1〜§7、§16〜§18、§19の全体の未決事項、§20）を収める。章・節の番号は分割前の要求定義書のまま使う。

## 1\. 文書の目的

本書は、利用者が**編集前動画を1本指定するだけ**で、企業内向けに収録されたトーク、対談、インタビュー、製品解説から、社内向け長尺版、短尺版、字幕、サムネイル、付帯情報を生成するソフトウェアに求められる要求を定義する。

本書は「何を実現すべきか」を定義するものであり、特定のプログラミング言語、動画編集ライブラリ、クラウドサービス、AIモデル等の実装方法は原則として固定しない。

基本方針は次のとおりとする。

1. 元動画を変更せず、自動処理結果を元発言、元映像、許可済み素材まで追跡できるようにする。
2. 元動画以外の入力は版付き既定設定から補完し、全設定を専用設定画面で確認、変更、初期化できるようにする。
3. 決定論的で意味を変えない規則は自動適用し、判断不能な結果は警告または候補として残す。
4. 読みやすさ、分かりやすさ、安全性を自動代理評価で機械検査する。
5. 自動代理評価を、人による知覚、理解、法的判断を実施した証拠とは表記しない。
6. 出力は社内限定かつローカル成果物を既定とし、任意に確認、修正、再生成できるようにする。

**用語（2026-10-06、FR-056）:** 画面上の呼称は「Project」とする。本書の承認済みの文面に残る「案件」は、画面の「Project」と同じものを指す（文面は承認時のまま変えない）。

# 2\. 背景と課題

## 2.1 背景

現在のHubらじおは、主に16:9の横長形式で収録された、10分から20分程度の企業内向けトーク動画である。

今後は、元動画だけを指定して次の社内向け成果物を一括作成したい。

1. 社内配信用の長尺版
2. 16:9横長版
3. 9:16縦型短尺版
4. 字幕焼き込み版と字幕なし版
5. 字幕、文字起こし、チャプター等の付帯物
6. サムネイル候補

YouTube、TikTok、LinkedIn等の仕様は出力profileの参考にするが、初期リリースは各サービスへの外部公開または直接投稿を行わない。

## 2.2 現状課題

- 編集者が動画を最初から最後まで見て、使える場面を手作業で探している
- カット、文字起こし、字幕、テロップ、画角変換を個別に行っている
- 長尺版と短尺版を別々に編集している
- 配信先ごとの縦横比や表示領域の違いに手作業で対応している
- テロップの用語、色、フォント、動きが動画ごとにばらつく
- 発言者名、製品名、社内用語の文字起こし誤りが発生する
- 10項目の必須入力と多段階レビューにより、元動画だけでは処理を開始できない
- 既定設定の値、根拠、適用範囲、初期値への戻し方を一か所で確認できない
- 元動画のどの部分から短尺動画を作成したか追跡しにくい
- 編集作業が特定の担当者に集中し、継続的な公開が難しい
- 機械試験と人の知覚評価が混同され、実施していない人手評価を完了扱いするリスクがある

# 3\. 目標

## 3.1 ビジネス目標

- 1本の元動画を選択してから、社内向け成果物の生成開始までの必須操作を1回の確認に収める
- 元動画以外の項目を安全な既定値で補完し、存在しない氏名、肩書、期限、URL、公開先を推測しない
- 1本の元動画から複数形式の動画を再利用可能にする
- 編集作業の属人性を下げる
- 長尺動画への入口となる短尺動画を継続的に制作できるようにする
- 重要な知識や発言を視聴者が短時間で理解できるようにする
- 既定の公開範囲を社内限定として管理する
- ブランド、字幕、音量、画面構成をシリーズ全体で統一する
- 編集結果を任意に確認、修正、再生成できるようにする
- 自動代理評価の合否、警告、未評価範囲を成果物ごとに確認できるようにする

## 3.2 成功状態

次の状態を満たすことを成功とする。

- 元動画を選択すると、安全な案件名、社内限定区分、版付き既定設定、成果物setが自動補完される
- 利用者が1回の確認で編集を開始できる
- 文字起こし、シーン候補、長尺、短尺、字幕、サムネイル候補が生成される
- 編集案ごとに、使用区間、削除区間、字幕、テロップ、画角、効果が確認できる
- 人が修正した内容を反映して動画を書き出せる
- 長尺版、短尺版、字幕ファイル、サムネイル案を一つの案件として管理できる
- 自動代理評価と任意のself-reviewを区別して確認できる
- 同じ入力、設定版、tool/model版から同じ編集計画を再生成できる

# 5\. 想定利用者

初期リリースの業務利用者は、現在のWindows標準ユーザーである**単一の利用者**とする。利用者は元動画の選択、自動結果と根拠の確認、任意の修正・self-review、社内限定成果物のローカル出力、設定変更を行える。

自動代理評価器、AI、Python worker、FFmpegは利用者または承認者ではない。actor SIDを持つ人の操作と区別したsystem actorとして記録する。将来複数利用者を追加する場合は、別要求、脅威分析、migrationを作成する。

# 6\. 入力要件

## 6.1 必須入力

システムは、案件作成時に**元動画ファイル1本だけ**を必須入力として受け付けること。

選択後、次を決定的導出または版付き既定設定で補完すること。

| 項目 | 初期値 |
| --- | --- |
| コンテンツ名 | 元ファイル名の拡張子を除いた名前 |
| 目的 | 社内向け再利用動画の自動編集 |
| 想定視聴者 | 社内視聴者 |
| 公開範囲 | 社内限定 |
| 言語 | 自動検出、不能時`ja-JP` |
| 出演者 | 匿名話者ラベル。氏名・肩書は空 |
| 期限 | なし |
| ブランド | 内蔵ニュートラル、ロゴなし |
| 成果物set | 16:9長尺1本、9:16短尺候補3本、字幕焼込版、字幕なし版、字幕file、サムネイル候補3枚 |

匿名、なし、ニュートラル等の安全な値を使い、氏名、肩書、期限、URL、外部公開先を推測してはならない。

## 6.2 任意入力

- 企画書
- 台本
- アジェンダ
- 出演者の正式な氏名と肩書
- 製品名、サービス名、社内用語の辞書
- 関連するPowerPointまたは画像
- 参考URL
- 使用可能なロゴ
- 使用可能なBGM、ジングル、効果音
- 編集してはいけない区間
- 必ず残す発言
- 外部公開不可の発言や情報
- 希望する動画時間
- 希望するトーン
- CTA、視聴後に促す行動

任意入力がないことを理由にquick startを拒否してはならない。

## 6.3 入力時の公開区分

quick startで作成する案件、素材、元動画内区間、編集版、出力物はすべて`社内限定`から開始すること。

- 子成果物が親より公開範囲を自動拡大してはならない。
- `Music/`由来素材は社内限定成果物だけに利用できる。
- 外部公開候補、外部公開承認済み等の既存区分はデータ互換のため保持できるが、本要求版の自動処理、受入、直接投稿の対象外とする。
- 公開不可または利用不可と利用者が指定した区間・素材は自動成果物に含めてはならない。

## 6.4 設定入力と版

- 全設定は専用設定画面から閲覧、変更できること。
- 各設定は現在値、初期値、用途、根拠区分、初期値に戻す操作を持つこと。
- 設定は「案件と出力」「編集」「字幕とグラフィック」「音声と素材」「プライバシーと保存」の5群にまとめること。
- 高度な設定は1段の展開UIへ置き、通常の動画指定画面へ露出しないこと。
- 新規案件には開始時の`DefaultSettingsProfile`のsemantic version、内容digest、snapshotを固定すること。
- 後日の既定値変更は既存版へ遡及適用しないこと。適用時は子`CompositionVersion`を作ること。
- 初期値、出典、根拠区分、適用範囲は[既定設定調査](../dev/research/default-settings-research.md)を正本とすること。

**UI/UX追補（2026-09-07承認）**

- 既存123項目を上記5群で欠落・重複なく保持し、高度な項目も閲覧・変更可能にすること。本追補で設定の定義・既定値・profile版を変更せず、型・範囲・profile／snapshotの厳密な検証を維持すること。
- 適用範囲（scope）を「新しい動画の既定値」（global）と「この動画」（案件）に分け、常時表示すること。案件scopeは実在する案件にだけ結び付け、未作成下書きに架空の案件IDを使わないこと。global変更は今後の新規案件に適用し、動画選択時に固定済みの下書きsummary／snapshotには自動反映せず、未適用と表示すること。
- 案件の開始時initial、既存Compositionと成果物の生成時snapshotは不変とし、案件の通常保存ではcurrentだけを変更すること。globalの初期化先はprofile初期値、案件の初期化先はinitialとすること。保存・初期化・file適用だけで既存動画を再処理せず、再適用は明示的な子版作成・再生成とすること。
- 通常保存は1項目単位とし、成功しても他項目の未保存draftを保持すること。globalと案件のrevisionを別管理し、同一scopeの競合ではdraftを保持して再読込へ誘導すること。scope／案件切替や全初期化で未保存値を捨てる場合は確認し、暗黙の一括保存・上書き・mergeをしないこと。

# 7\. 基本処理フロー

1. 利用者が元動画1本を選択する
2. システムが安全な案件名を導出し、社内限定の版付き既定設定と成果物setを要約表示する
3. 利用者が`編集を開始`または取消を選ぶ。その他の項目入力は要求しない
4. 元動画を管理workspaceへ非破壊取込し、形式、stream、PTS、全編decode、容量を検査する
5. 代理動画、波形、preview索引、文字起こし、発話時刻、匿名話者、客観的な編集候補を作る
6. 明示カット、構造的な完全一致反復、版付き無音規則等の決定論的処理を子版へ自動適用する。曖昧な処理はwarningまたは候補に留める
7. 長尺、短尺、字幕、画角、音声、BGM、サムネイル、付帯情報を同じCompositionから生成する
8. codec、decode、duration、A/V同期、字幕、画面領域、音量、来歴を自動代理評価する
9. 自動代理評価が判断不能でも、社内限定成果物は未評価範囲とwarningを記録して出力できる。技術的破損または来歴欠落は出力を拒否する
10. 利用者は任意にpreview、差分、根拠へ移動し、修正、self-review、再生成できる
11. QC済み成果物だけをローカル納品領域へ昇格し、hash、元区間、設定版、編集履歴、評価結果を保存する

# 19\. 未決事項

- production品質の精度、処理時間、moving-video/audio fidelityの合格値
- 実platform表示から測定する版付きUI maskの値と更新周期
- 単一EXEのクリーンWindows受入、許容起動時間・必要容量、実配布経路・署名主体・対象policyでの信頼証拠
- 将来のsigned MSIX、upgrade、rollback、uninstall、read-only install境界の実環境証拠（現行の起動技術検証の必須gateにはしない）
- 最終配布物の完全なSBOM、notice、CVE、codec/patent条件
- backup保存先と、利用者が明示するまで未設定とする保持期間
- 将来外部公開scopeを追加するか。追加する場合は本要求版とは別に要求、権利、privacy、security、運用gateを決める
- 既存Clipchamp編集プロジェクトとの受け渡しを追加するか

未決事項があることを、source-only社内限定vertical sliceの実装開始を妨げる架空の外部承認gateへ読み替えてはならない。ただし、該当機能または配布を完了した証拠なしにPASSとしてはならない。

# 20\. 完了条件

4. 旧203 task baselineを歴史snapshotとして保全し、新要求への`維持`、`変更`、`削除`、`新規`を再分類する。

production実装、実素材render、human evaluation、外部公開、cross-account試験、社内法務承認は、この文書自体の完了条件ではない。
