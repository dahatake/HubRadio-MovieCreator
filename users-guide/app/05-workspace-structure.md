# Workspace のフォルダー構造

HubRadio MovieCreator が作るファイルは、すべて **Workspace（ワークスペース）** という 1 つのフォルダーにまとまります。自分でファイルを探したい、退避（バックアップ）したい、容量を調べたいときは、このページを見てください。

> 先に知っておくこと
> - **選んだ元動画は、Workspace の `original` フォルダーにコピーして取り込まれます**。選んだ元の場所のファイルは動かず、Project を削除しても元の場所の元動画は消えません。
> - 作った動画を **別のフォルダーに取り出したい** ときは、Workspace の中を探さず、「仕上がり」画面の書き出し機能を使います（[7. 成果物の書き出し](#7-成果物の書き出しworkspace-の外へ)）。

## 1. Workspace の場所と変え方

| 項目 | 内容 |
|---|---|
| 既定の場所 | アプリの実行ファイル（インストール先）のフォルダーの直下の `workspace`（例: `C:\Apps\HubRadio\workspace`） |
| 変える場所 | 設定画面の「Workspaceフォルダー」の欄。入力欄に直接入力するか、「参照…」でフォルダーを選び、**「保存」** を押します（選ぶだけでは変わりません） |
| 設定の保存先 | `%LOCALAPPDATA%\HubRadio.MovieCreator\workspace-location.json`（`{"version":1,"path":"<絶対パス>"}`）。**Workspace の中ではなく、アプリ側の設定フォルダー**にあります |
| 初期値に戻す | 設定画面の「初期値に戻す」（`workspace-location.json` を削除します。フォルダーとデータは削除されません） |
| 反映のタイミング | 「保存しました。アプリを再起動すると新しい場所を使います。」と出たら、**アプリを再起動**してから新しい場所が使われます。画面には「現在使っている場所」「初期値」「次回の起動から使う場所」が表示されます |
| 使える場所 | ローカルのドライブ上の、空のフォルダー（または既存の Workspace）。使えない場所は保存されず、「この場所は使えません。…」と表示されます |

**重要:** 場所を変えても、**今ある Project のファイルは自動では移動されません**。新しい場所へ移したいときは、アプリを終了してから、`workspace` フォルダーの中身をそのまま新しい場所へ移し、その場所を設定してください。

`workspace-location.json` が壊れている、または保存先のドライブが使えないときは、アプリは別の場所へ黙って切り替えず、起動に失敗します。`workspace-location.json` を削除して再起動すると既定の場所に戻ります（保存先のデータは削除されません）。

## 2. 全体の構造

```text
<Workspace>\                         例: C:\Apps\HubRadio\workspace
├─ hubradio.db                       Project・Job・成果物などの記録（データベース）
├─ .project-folders.json             Project とフォルダー名の対応表（隠しファイル。触らない）
├─ projects\                         Project ごとの作業ファイルと成果物
│   ├─ hubradio-sample\              ← Project 名と同じ名前のフォルダー
│   │   ├─ original\                 取り込んだ元動画のコピー
│   │   ├─ proxy\                    確認用の軽い動画
│   │   ├─ analysis\                 文字起こしなどの解析結果
│   │   ├─ compositions\             カットや構成の設計
│   │   ├─ previews\                 プレビュー
│   │   ├─ renders\                  仕上げた動画（長尺・短尺・サムネイルなど）
│   │   ├─ deliveries\               保存（納品）した成果物と字幕ファイル
│   │   ├─ evidence\                 受領や自動評価の証跡
│   │   └─ staging\                  作業中の一時置き場（完了すると中身は移されます）
│   └─ ほかの Project 名\ …
├─ job\                              Job の実行履歴（1 Job につき 1 ファイル）
└─ backups\                          データベースのバックアップ（backup-<ID> のフォルダー）
```

Project のフォルダーの中身（`original`〜`staging`）は、成果物の種類ごとに分かれています。**フォルダーの数や中身は、実行した処理によって増減します**（まだ作られていないフォルダーは存在しません）。

## 3. 主なフォルダー・ファイルの役割

| 場所 | 役割 | 手で触ってよいか |
|---|---|---|
| `hubradio.db` | Project・Job・成果物・履歴の本体の記録 | **触らない**（アプリを終了してコピーする以外は不可） |
| `.project-folders.json` | Project の識別とフォルダー名の対応 | **触らない**（編集すると Project が見つからなくなります） |
| `projects\<Project 名>\` | その Project の作業ファイルと成果物 | 中身の**閲覧とコピーは可**。移動・名前変更・削除は不可 |
| `projects\<Project 名>\renders\`・`deliveries\` | 仕上がった動画・サムネイル・字幕 | **コピーして使うのは可**（元は動かさない） |
| `projects\<Project 名>\staging\` | 作業中の一時ファイル | 処理中は触らない |
| `job\job-<作成日時>-<Job ID>.json` | Job の実行履歴（最大 1000 件。超えると古いものから削除） | 閲覧・コピーは可。**書き換えない** |
| `backups\` | データベースのバックアップ | 退避用のコピーは可。書き換え・削除は不可 |

> 「触ってよいか」の判断に迷うときは、**アプリを終了してから、フォルダーごとコピーする**のが最も安全です。アプリの起動中に、Workspace の中のファイルを移動・削除・名前変更しないでください。

## 4. Project 名とフォルダー名

Project のフォルダー名は、**Project 名と同じ**です（例: Project 名が `hubradio-sample` なら `<Workspace>\projects\hubradio-sample`）。内部では Project を別の識別子（GUID）で管理しているため、**名前を変えても Job・成果物・履歴は失われません**。

### 使えない名前

Project 名は Windows のフォルダー名として使える名前に限ります。次のいずれかに当てはまると、作成・名前変更の時点で拒否され、理由が表示されます。Project もフォルダーも作られず、変わりません。

| 使えない名前 | 例 |
|---|---|
| 空、または空白だけ | （空欄） |
| 使えない文字を含む（`\` `/` `:` `*` `?` `"` `<` `>` `\|` と制御文字） | `A/B`、`特集:春` |
| 先頭が空白、または末尾がドット・空白 | `特集.`、`特集 ` |
| Windows の予約名（`CON`・`PRN`・`AUX`・`NUL`・`COM1`〜`COM9`・`LPT1`〜`LPT9`。拡張子付きも不可） | `CON`、`nul.txt` |
| 80 文字を超える | — |
| 同じ Workspace の別の Project と同じ名前（**大文字と小文字は区別しません**） | `Sample` と `sample` |

### 名前を変えたとき

「Project名を保存」で名前を変えると、**同じ操作の中でフォルダー名も新しい名前になります**。ファイルが使用中などで変更できなかったときは、Project 名もフォルダー名も元のままで、データは失われず、理由が表示されます。名前の変更中にアプリが止まっても、次の起動で完了するか、元の名前のままで使えます（コピー・削除はしません）。

## 5. GUID 名のフォルダーからの移行

以前のバージョンで作った Project は、フォルダー名が `projects\<英数字とハイフンの長い ID（GUID）>` になっています。**アプリを起動すると、Project 名のフォルダーに自動で変わります**（同じドライブ内の名前の変更だけで、コピーや削除はしません）。

- 移行の前後で、Project・Job・成果物・履歴は失われません。移行後も、これまでどおり表示・再生・再作成できます。
- 何度起動しても結果は同じで、途中で中断しても、次の起動で続きから完了するか、元の GUID 名のままで使えます。
- **移行できない Project**（Project 名が上の「使えない名前」に当たる、同じ名前の Project が複数ある、同じ名前のフォルダーがすでにある、など）は、**GUID 名のフォルダーのまま使い続けます**。データは変わらず、移行できなかったことが表示されます。名前を直せば、その後の起動や名前変更でフォルダー名も揃います。

> 上の「場所を変えても今ある Project のファイルは移動されない」（[1.](#1-workspace-の場所と変え方)）は、**Workspace の場所**を変えたときの話です。Workspace の**中**のフォルダー名の移行とは別です。

## 6. 画面とフォルダーの対応

| 画面（タブ） | 見られるもの | 主に対応するフォルダー・ファイル |
|---|---|---|
| Project 一覧 | Project のカード | `projects\<Project 名>\`、`hubradio.db` |
| 元動画 | 元動画の情報、予定成果物、Project 名の変更 | `projects\<Project 名>\original\`（元動画のコピー）、`proxy\`（確認用の動画） |
| ジョブの状態の確認 | Job の進み具合・失敗理由・再試行 | `job\`（履歴）、`hubradio.db`、`analysis\`・`compositions\`・`previews\` |
| 仕上がり | 動画の再生、成果物、字幕、サムネイル、自動評価 | `renders\`、`deliveries\`、`evidence\`、`analysis\` |
| 設定 | Workspace の場所、各種設定 | `%LOCALAPPDATA%\HubRadio.MovieCreator\workspace-location.json`（Workspace の外）、`hubradio.db` |

「保存」タブはありません（廃止されました）。作った動画を取り出すには、「仕上がり」画面から書き出します。

## 7. 成果物の書き出し（Workspace の外へ）

「仕上がり」画面で Job を 1 つ選び、その Job の動画（長尺、短尺のクリーン版、短尺の焼き込み版）とサムネイルを、**自分が選んだフォルダー**へ保存（書き出し）できます。

- **書き出し先は、Workspace の中ではありません。** 保存先は「参照…」で選ぶか、直接入力して指定します。
- 書き出しは Workspace のファイルを**コピー**するもので、Workspace の中身は変わりません。書き出したファイルを消しても、Workspace の成果物は残ります。
- 保存先に同じ名前のファイルがあるときは、上書きせず、名前に連番を付けて別のファイルとして保存します。
- ファイル名には Project 名・Job 名（なければ作成日時）・成果物の種類が入ります。
- 終わると、保存できた件数と、保存できなかったファイルの理由が表示されます。

Workspace のフォルダー（`renders\` など）から直接コピーするより、**書き出しを使う方が、ファイル名が分かりやすく、取り違えを防げます**。

## 8. アプリの更新・削除と Workspace

- アプリの実行ファイルを**入れ替え（更新）しても、Workspace は残ります**。
- アプリの実行ファイルを**削除しても、Workspace は自動では削除されません**。ただし、既定の場所（実行ファイルのフォルダーの直下の `workspace`）は、**そのフォルダーごと削除すると Workspace も失われます**。実行ファイルのフォルダーを消す前に、`workspace` フォルダーを別の場所へ退避してください。
- 退避するときは、アプリを終了してから `workspace` フォルダーごとコピーします。

## 9. 困ったとき

| 症状 | 対処 |
|---|---|
| 起動しない（Workspace の場所の設定が壊れている） | `%LOCALAPPDATA%\HubRadio.MovieCreator\workspace-location.json` を削除して再起動（既定の場所に戻ります） |
| Project が一覧に出ない | アプリを終了し、`workspace` の中を手で動かしていないか確認します。動かしたものは元に戻してください |
| フォルダー名が長い ID のまま | [5. GUID 名のフォルダーからの移行](#5-guid-名のフォルダーからの移行)の「移行できない Project」を確認してください |
| 容量が足りない | `projects\<Project 名>` の大きさを見て、不要な Project を画面から削除します（フォルダーを直接消さないでください） |
