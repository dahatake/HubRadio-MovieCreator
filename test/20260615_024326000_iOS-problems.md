# 動画生成 問題レポート

- 初回記録日時（UTC）: 2026-08-26T17:06:13.9521834Z
- 入力: sample/20260615_024326000_iOS.MOV
- 予定出力: test/20260615_024326000_iOS.MOV

## 問題1: 空のstderrをwrapperが拒否した

### 現象の説明

FFmpeg子プロセス終了後、動画生成wrapperが`ParameterBindingValidationException`で終了しました。最終出力とmanifestはcommitされず、stagingファイルは清掃されました。

### 根本原因

`Invoke-Tool`はFFmpegのstderrを必ず`Protect-SensitiveText`へ渡していました。FFmpegがstderrを出さない場合は空文字になりますが、同関数の`Text` parameterが空文字を許可していなかったため、PowerShellのparameter bindingが失敗しました。

確認できた例外:

- 型: `System.Management.Automation.ParameterBindingValidationException`
- message: `Cannot bind argument to parameter 'Text' because it is an empty string.`
- output committed: `False`
- manifest committed: `False`

### 考えられる解決策の選択肢

1. `Protect-SensitiveText`で空文字とnullを許可し、空文字をそのまま返す。
2. 呼出側でstderrが空の場合だけ秘匿関数を呼ばない。
3. `Invoke-Tool`で空stderrを固定文字列へ置き換える。

### 推奨する解決策

選択肢1を採用し、`[AllowEmptyString()]`と`[AllowNull()]`を指定した上で、空値を即時returnするよう修正しました。

### 選択理由

stderrが空であることは成功時の正常な状態です。秘匿関数自身が空値を扱う方が、全呼出箇所で条件分岐を重複させず、実際のstderr内容も改変しない最小修正だからです。

## 問題2: 問題レポートの`test`がタブ化した

### 現象の説明

初回問題レポートの予定出力が`test/...`ではなく、先頭がタブに置き換わった`est/...`として表示されました。

### 根本原因

PowerShellのdouble-quoted here-string内でMarkdownの開始バッククォートと`test`が連続し、`` `t ``がタブescapeとして解釈されました。

### 考えられる解決策の選択肢

1. 生成レポートのパス表記からMarkdownバッククォートを外す。
2. バッククォート自体をPowerShell用にescapeする。
3. 文字列の組立方式をsingle-quoted templateへ変更する。

### 推奨する解決策

選択肢1を採用し、入力・出力パスは通常のMarkdownテキストとして出力するよう修正しました。

### 選択理由

コード表示装飾は要件ではなく、パスの正確性が優先されます。escapeを増やさず再発条件を除去する最小変更だからです。
